## Methodology notes and caveats

- This subagent cannot operate a live browser. Cases requiring visual interaction, authenticated bank data, network jobs, push notifications, backend state, or a human were marked Blocked unless static code evidence proved a definite Pass or Fail.
- Production HTML was fetched 2026-09-25 and does **not** contain the newly staged CFO-in-chat changes; it is the pre-chat-intent stable build. The Guide is deterministic keyword matching — no LLM in the loop.
- Several Red Lines cases carry `expected: FAIL` in the suite (the author's anticipation of a violation). Verdicts here are independent and evidence-based: Pass = no violation committed.
- Detection agent judged normalizeMerchant cases Pass where the behavioral pass-criteria held, noting the format deviation (space-joined, not hyphenated canonical ids).
- 2-006 noted as strict fail (qUrgency(2 days)=4, max 5 only at ≤1 day) though the "steep inside 48h" property holds — flagged for grader override.
- 8-018 passed on functional equivalence (`verified_date` populated on all verified routes) though the literal field name `terms_captured_at` does not exist.
- Nothing was modified. All evidence is quoted from harness outputs or prod.html.
